# Cycle Detector 검증

기존 `5.EDA_0_Cycle.ipynb`에서 Outlier Cycle Candidate가 8개만 생성된 원인을 검증한다.

## 검증 질문

### Q1
Outlier segment 중 기존 detector의 최소 길이 조건인 30 samples를 통과하는 구간은 몇 개인가?

### Q2
길이 조건을 통과한 segment에서 AI2 peak가 몇 개 검출되는가?

- peak 0개 → cycle 생성 불가
- peak 1개 → cycle 생성 불가
- peak 2개 이상 → peak-to-peak cycle 생성 가능

### Q3
기존 segment별 adaptive prominence 때문에 Outlier peak가 누락되는가?

Normal 데이터에서 prominence 기준을 정해 고정한 detector와 비교한다.


# 결론
Q1 결론
Outlier 데이터는 총 21개의 연속 segment로 구성되며, 이 중 11개가 기존 Cycle Detector의 최소 길이 조건인 30 samples를 만족하지 못했다. 따라서 10개 segment만 완전한 Cycle 검출 대상으로 사용되었다.

Q2 결론
분석 가능한 10개 segment에서는 모두 최소 1개의 AI2 peak가 검출되었지만, 4개 segment에서는 peak가 하나만 검출되어 peak-to-peak Cycle을 구성할 수 없었다. 나머지 6개 segment에서 총 8개의 Cycle Candidate가 생성되었다. 따라서 8개라는 결과는 짧은 segment와 완전한 peak pair 부족에 의해 주로 설명된다.

Q3 결론
기존 adaptive prominence와 Normal 데이터에서 얻은 fixed prominence를 비교한 결과, Outlier의 총 peak 수는 모두 18개, Cycle Candidate 수는 모두 8개로 동일하였다. 따라서 adaptive prominence가 8개 Cycle만 검출된 주원인은 아니다. 다만 prominence와 peak distance를 소폭 변경했을 때 Outlier의 Cycle Candidate 수가 5~14개로 변해 Normal보다 detector parameter에 민감한 것으로 나타났다. 따라서 Outlier의 8개 Cycle은 전체 데이터의 실제 Cycle 수가 아니라 현재 detector 조건에서 확보된 완전한 Cycle Candidate로 해석한다
